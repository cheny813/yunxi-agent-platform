## 运维可视化端口（本仓库 docker-compose 管理，可选）

由 `docker-compose.yml` 一键启动，仅用于链路追踪采集与向量库管理可视化，不影响核心业务（40001）。关闭：`docker compose stop jaeger otel-collector attu`。

| 端口 | 服务 | 说明 |
|------|------|------|
| 4317 | OTel Collector (gRPC) | OTLP gRPC 接收端口，应用 trace 上报入口之一 |
| 4318 | OTel Collector (HTTP) | OTLP HTTP 接收端口；应用默认上报 `http://127.0.0.1:4318/v1/traces`。根路径 `/` 返回 `404 page not found` 属正常（4318 是接收端口，非网页，无对应路由 handler） |
| 16686 | Jaeger UI | 链路追踪可视化，访问 `http://127.0.0.1:16686`，Service 选 `yunxi-agent-platform` |
| 8000 | Attu UI | Milvus 向量库 Web 管理界面，访问 `http://127.0.0.1:8000`，连接 `milvus:19530` |

完整调用链：应用 → OTel Collector (4318/4317) → `otlp/jaeger` exporter → Jaeger (16686)。

## 端口分配规则

1. **所有业务服务统一使用 `4xxxx` 端口范围**
2. **跨项目不可重复**：yunxi-agent-platform 和 yunxi-mcp-servers 共享同一个端口空间
3. **新增服务按类别分配**：参考上方范围划分表
4. **禁止硬编码端口**：所有端口通过 `application.yml` 或环境变量配置
5. **AgentScope集成策略**：将AgentScope相关服务接入本框架系统
6. **记忆系统**：由 agentscope-harness 内置双层记忆替代，无需独立服务
7. **外部服务端口标准化**：所有外部服务端口需明确记录和保持一致
8. **验证机制**：建立端口配置与实际使用的一致性验证机制
9. **修改此文档时同步更新**：`yunxi-agent-platform/docs/端口规划.md` 和 `yunxi-mcp-servers/端口快速参考.md`
